# Data model and outputs

Every reported value needs three pieces of context: its data grain, the observation
or run that produced it, and whether it is a fact or inference.

## Conventions

- Prices are public asking prices in **Toman**, not Rial and not transaction prices.
- `year_jalali` is a Jalali production year. Gregorian equivalents are separate
  fields when available; a year conversion is not an exact date conversion.
- Monitor timestamps are timezone-aware UTC. Scheduled slots retain the named local
  timezone used to compute them.
- Raw Persian text can coexist with normalized text and parsed numeric values.
- Canonical advertisement identity uses the platform ad ID and canonical URL.
- Advertisement grain and inferred physical-vehicle grain are never interchangeable.
- Null, unavailable, hidden, negotiable, parse failure, and numeric zero have
  different meanings.
- A database or export being generated by this project does not make it safe to
  publish. Privacy protections differ by component.

## Base scraper

The source of truth is `output/bama_ads.sqlite`.

| Table | Grain and purpose |
|---|---|
| `runs` | One row per invocation and its search/termination evidence |
| `discovered_ads` | One row per canonical advertisement in the accumulated inventory |
| `ad_details` | One parsed payload per completed advertisement |
| `ad_media` | One row per advertisement media item |
| `raw_attributes` | One original key/value attribute per advertisement |
| `scrape_errors` | One recorded failure per stage/attempt context |
| `network_candidates` | One observed JSON endpoint candidate |
| `discovery_checkpoint` | Resumable discovery progress |

Exports in `output/` include `bama_ads.csv`, `bama_ads.jsonl`, `bama_ads.parquet`,
`bama_media.csv`, `bama_errors.csv`, `bama_discovered.csv`, `run_summary.json`, and
`network_candidates.json`; the manifest also identifies the SQLite source path. CSV
uses UTF-8 with BOM for spreadsheet compatibility. Parquet is a derivative and can
be regenerated.

List/dict fields such as badges, media URLs, raw attributes, JSON-LD, and parser
warnings are JSON-encoded in flat exports so one row remains one advertisement.
Missing values stay null rather than becoming zero. Raw text is retained beside
normalized values, for example `price_text`/`price_toman` and
`mileage_text`/`mileage_km`.

The base parser removes known contact-field keys but does not redact arbitrary
contact text inside descriptions. Base exports and debug captures are potentially
personal data even after a passing base audit.

## Deep enrichment

The source of truth is `deep_scraper/data/bama_deep.sqlite`.

| Table family | Grain and purpose |
|---|---|
| `deep_runs`, `deep_checkpoint`, `deep_queue`, `deep_errors` | Run, work, and failure provenance |
| `ad_deep` | One merged public advertisement record |
| `ad_media_deep`, `ad_raw_attributes`, `ad_field_conflicts` | Media, raw fields, and API/HTML disagreements |
| `trim_reviews`, `trim_spec_groups`, `trim_specs`, `trim_specs_typed` | Model-trim review and long-form specification data |
| `spec_key_catalog` | Generated specification-key dictionary |
| `price_keys`, `price_series`, `price_points`, `price_brands`, `price_hierarchy` | Model-trim price-reference data |
| `dealers`, `dealer_ads` | Public dealer profiles and listing inventory |

`v_trim_specs_wide` is generated from the long specification representation. A trim
attribute describes a model-trim, not an individually observed car.

The export command writes UTF-8-BOM CSVs for the main and normalized tables,
`ads_deep.jsonl`, nested `ads_full.jsonl`, selected Parquet tables, a generated
`data_dictionary.md`, `manifest.json` with hashes/counts, and the point-in-time
`bama_deep_snapshot.sqlite`. Numeric fields whose sources disagree preserve text,
parsed numeric, and raw representations plus reconciliation status.

## Monitoring database

The monitor uses the same logical schema in SQLite and PostgreSQL. Migrations under
`migrations/` are the schema authority.

| Table | Grain and purpose |
|---|---|
| `monitoring_runs` | One invocation with trigger, slot, health, and counters |
| `advertisements` | One platform advertisement with current derived state |
| `daily_ad_observations` | One immutable run × advertisement observation |
| `advertisement_detail_checks` | Proof that one advertisement was checked in one run |
| `advertisement_snapshots` | Content snapshot written when changed or required |
| `advertisement_events` | Immutable state/event audit trail |
| `price_changes` | One detected price change for an advertisement and run |
| `detail_verifications` | Classification of a missing advertisement's detail page |
| `repost_links` | One possible parent/successor advertisement relationship |
| `vehicle_entities` | One inferred physical vehicle across linked advertisements |
| `sale_validation_samples` | One manually labelled calibration example |
| `scrape_errors`, `alerts`, `run_locks` | Operational evidence |
| `production_schedule`, `missed_schedule_slots` | Genuine-history boundary and missed slots |

A detail check answers “was the page examined?” A snapshot answers “what content was
stored?” An unchanged daily check may reference an older matching snapshot.

Database constraints enforce unique observations, idempotent events, replay-safe
price changes, and one genuine run per schedule slot. Manual, deployment-test,
simulation, and backfill runs do not own production slots.

### Daily reports and snapshots

Daily reports are partitioned by date and include run summary, inventory, transitions,
missing/removal/reappearance files, possible reposts, sale evidence, price changes,
errors, duration exports, filter exits, survival/cohort data, market breakdowns,
vehicle durations, an HTML dashboard, and a manifest.

CSV files keep stable headers even when empty. Rows carry run ID, scheduled slot,
run start/finish, search-configuration hash, and component versions.

Daily snapshots are immutable, partitioned by their true scheduled slot, and
published only after validation. `latest_valid.json` advances atomically and never
points at an invalid run. An `--allow-invalid` forensic export cannot advance it.

Those guarantees describe `export_daily_snapshot`; they do not mean every deployment
unit calls it correctly. The current systemd/Docker timer units invoke a manual
`run-daily` without snapshot export. See
[Project status](project-status-and-limitations.md#unattended-deployment-blockers).

## EDA datasets

| Dataset | Grain | Typical questions |
|---|---|---|
| `advertisement_cross_section` | Advertisement at selected valid run | Composition, asking price, attributes, current state |
| `longitudinal_panel` | Monitoring run × advertisement | Changes, observation patterns, temporal comparisons |
| `vehicle_entity_dataset` | Inferred physical vehicle | Repost-aware duration and vehicle-level outcome |

EDA outputs live below the configured report directory and include dataset exports,
schema inventory, data dictionary, integrity findings, statistical tables, charts,
HTML report, and `eda_manifest.json`.

The full report writes CSV and Parquet for the cross-section and vehicle-entity
datasets, but the longitudinal panel is Parquet-only. `build-datasets` can write CSV
for all three datasets when CSV export is enabled; these two commands therefore have
slightly different artifact sets.

The manifest records selected run, versions, configuration fingerprint, backend,
row counts, exclusions, warnings, enrichment coverage, and temporal rules. It is the
first file to inspect before using any generated table.

The EDA API intentionally exposes query methods and does not run migrations, but the
shared SQLite connector is not opened in OS-level read-only mode. Pointing it at a
missing SQLite URL can create a file and WAL-related state. Enforce read-only access
outside the process when required.

## Censoring fields

- `first_seen_at` and `last_seen_at` bound this installation's observation.
- `published_at` is usable only with reliable provenance.
- `left_truncated` means the listing's earlier market life was not observed.
- `event_observed` means disappearance was observed, not sale.
- Duration lower/upper fields retain the interval between last seen and first missed.
- Vehicle durations span linked advertisements and state their listing/repost counts.

See [Methodology](../explanation/methodology.md) for interpretation and
[Responsible use](../explanation/responsible-use.md) for publication constraints.
